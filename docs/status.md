# Стан проєкту

## Поточна готовність — 2026-11-14

У репозиторії є повний склад застосунку: API, web, приватний асистент і widget, ML-пакет, усі десять міграцій БД, тести, ресурси, Compose, резервне копіювання та CI/release workflows. Локальний Docker-стек з agent profile запущений і доступний на http://localhost:8080. Готовність компонентів і результати перевірок наведені нижче.

Загалом у перелічених suites успішно виконано **1189 тестів**: 1188 із компонентних suites та новий регресійний тест build topology. Повторний запуск тих самих п’яти Docker-інтеграційних тестів не додається до цього числа. Пропуски не зараховано як успішні результати. Окремі smoke-перевірки не додаються до цього числа.

### Межі перевірки

- Опційні embeddings і dense/reranker моделі не встановлювалися; дороге навчання не запускалося.
- Живий OpenAI-сумісний провайдер перевірено одним коротким запитом; це не повний eval моделей. Gemini й Anthropic не викликалися. Налаштування провайдерів описані в [інтеграції асистента](assistant-integration.md).
- Unit-запуски можуть повідомляти про deprecation у залежностях; web/widget build попереджає про великі chunks.
- Оцінка production-готовності й комерційних умов джерел даних залишається окремою роботою.

### Пакет сценаріїв сівозмін для команди

[Окремий пакет](../research/rotation-handoff/README.md) містить API 2.13.0, кліматичні сценарії NASA для 2040-х і офлайн-прогін Sutherland за 2026–2028 роки. Для сезону 2027 є окремий приклад із рівними вагами історичних сезонів і проєкцій NASA. Довідник містить 20 перевірених записів про гібриди й сорти з польових випробувань, доступних через `GET /api/rotations/cultivar-references`. Фінансові показники повертають валову виручку й виручку після вартості насіння. Інструкція для UI та асистента пояснює запуск і межі розрахунку. Команда запускає пакет із його каталогу. Кліматичний API та локальні прогони автоматично підключають [рушій водного балансу Руслана](../research/rotation-handoff/vendor/ruslan/README.md), зафіксований на коміті `468a03d`. Кліматичний API приймає вже вибрану дату й один посів на календарний рік. Пакет працює окремо від основного застосунку.

З вбудованим рушієм пройшли 18 тестів кліматичного пакета й 17 тестів гібридного прогнозу. У чистій копії без `FIELDSHIFT_RUSLAN_DIR` запит Sutherland 50/50 повернув HTTP 200, а відповідь збіглася зі збереженим результатом. Перенесення тієї самої погоди між календарними роками відтворило 66 сезонів культур і обидві сівозміни. Локальна перевірка HTTP підтвердила приклад Marsden і фільтр сортів сої в Sutherland. Офлайн-прогін Sutherland 50/50 відтворив збережений результат.

Інструкції запуску: [README](../README.md). Правила відкату: [план роботи](roadmap.md).

### Виправлення збірки спільного образу API

`build` у спільному Compose anchor створював кілька паралельних exporters для `field-shift-api:local`. На Docker 29 / BuildKit це відтворило помилку `image already exists`. Визначення `build` тепер належить лише сервісу `api`; migrate, dispatcher, refresh і workers використовують той самий готовий образ. Регресійний тест перевіряє унікальність image tags у реальному Compose build plan, падає на попередній конфігурації та проходить після виправлення.

### Інтеграція онбордингу полів, 2026-11-14

- Додано пошук країни й регіону, перехід за координатами, супутникову карту, автоматичне визначення та ручне редагування меж, анкету й демоплан сівозміни.
- Міграція `0011_field_onboarding` додає таблицю чернеток онбордингу. Alembic визначає її як єдину вершину графа міграцій.
- На версії після інтеграції пройшли 329 неінтеграційних тестів API, 82 вебтести, TypeScript і production build, Ruff для змінених Python-файлів, перевірка конфігурації Compose і тест унікальності тегів образів у плані збірки.
- Запуск повного стеку з Delineate Anything v2, перевірку живих постачальників знімків і інтеграційні тести PostgreSQL/Redis на цій версії ще не виконано. Для запуску моделі див. [документацію](boundary-model.md).

### Виправлення інтеграції онбордингу

- «Вода» і «Сівозміни» читають доступність зрошення з анкети вибраного поля. Для старих полів і невідомої відповіді діє налаштування господарства.
- Планувальник використовує відому історію та дозволені культури з анкети. Базові варіанти враховують пріоритет фермера, а планувальник показує його поруч із налаштуваннями. Оцінка планувальника базується на заданих правилах і перевагах.
- Локально пройшли Ruff, 57 вибраних API-тестів, 82 вебтести, TypeScript, production build і перевірка конфігурації Compose. Повний HTTP-набір API зависає під час створення сокета у Windows; PostgreSQL/Redis і збірка Docker не запущені через недоступний Docker Engine.
- На CPU пройшли перевірка контрольної суми ваг, прогрів і сегментація поля на знімку Бондуранта. CI збирає окремий образ Delineate Anything v2 та перевіряє готовність, обробку некоректного запиту й маску поля на локальному знімку. Результат нового завдання CI буде доступний після оновлення PR.

Для інтеграції з плануванням у [#7](https://github.com/matveyola/nasa_field_shift/issues/7) після об’єднання гілок створити одну ревізію `0013_merge_planning` з батьківськими ревізіями `0011_field_onboarding`, `0011_field_profiles` і `0012_planning_runs`. Команда в `apps/api`:

```sh
uv run --no-sync alembic merge --rev-id 0013_merge_planning -m "Merge field onboarding and planning" 0011_field_onboarding 0011_field_profiles 0012_planning_runs
```

На спільному дереві міграцій із `nazar-jobs` (`266b7f0`) перевірено шість шляхів оновлення в SQLite. Дані полів, онбордингу й планування збереглися. Для спільної інтеграції виконати `alembic heads`, оновлення й перевірку відновлення на PostgreSQL.
