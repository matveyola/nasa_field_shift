# Global model selection evidence — 2026-11-14

Published metrics are cited author results, not local reproductions. Implemented
experiments and their actual local metrics are listed separately in this document's
companion reports. No universal SOTA or global field-yield validation is established.

## Decision now

Keep the current versioned AquaCrop-OSPy adapter as its explicitly limited baseline. Add the audited Ruslan layered water/snow balance as a separately selected **experimental water-only** model, with user-supplied local crop dates, stage lengths, soil and initial conditions, and a provenance registry. Do not import Iowa calendar rules or call the new model a globally calibrated crop/yield forecast. Preserve continuous profile/snow state through fallow and successive crops; reject overlapping crops because this is succession, not simultaneous intercropping.

A global catalog can honestly describe all eight crops while a model abstains on a subset. Seven non-paddy crops can have reference FAO water-parameter records without claiming local accuracy. Rice needs an explicit paddy/upland distinction; the proposed freely draining bucket should abstain on paddy rice. Pea is not interchangeable with chickpea, cowpea, pigeonpea or faba bean. No reviewed model or benchmark supplies verified universal eight-crop accuracy.

For yield, start with data-qualified, crop/region-specific mean/trend, Ridge, RF/GBDT challengers on actual pre-sowing or explicit in-season cutoffs. Select by held-out error and uncertainty coverage, not family reputation. Parameter-calibrated process models should follow where field management/soil/cultivar data support them. Frozen EO embeddings are a later challenger once labels and acquisition cutoffs are reliable. Consume operational atmospheric forecast products on CPU rather than trying to train/run an atmospheric foundation model locally.

## Existing Ruslan work: reuse and limits

Inspected source `468a03d79e596e9daab4cfdb20e9e0c8e2b83a92`, branch `research/fieldshift-tasks-1-4`, original author Ruslan (`ruslankoritich@gmail.com`), `research/fieldshift_tasks/fstasks`.

- `balance.py` has useful 0.1 m layer storage, explicit snow water equivalent, degree-day melt, fallback frozen-soil runoff, optional drainage and continuous mutable profile state. Its budget tracks water above wilting point; root-zone reserve is mm, not surface volumetric moisture.
- `crops.py` says its values are table/adapted/assumption, and table values still need PDF verification. It hardcodes dormancy Dec 1–Apr 1 and Central Iowa defaults. Maize stage durations cite an Idaho row; soybean flowering uses days after planting rather than a dynamic photoperiod model. These cannot be relabeled global parameters.
- `soil.py` curve numbers are hydrologic group B. Snow threshold 0 C, melt 3 mm/C/day, 7-day air-mean freeze threshold -1 C, frozen CN95, residue0.3 and uniform initial wetness0.5 are assumptions, not measurements. Root depth silently clips to profile depth; layer count rounds depth/0.1. A new adapter should validate these boundaries rather than silently borrow defaults.
- Require finite/physical soil/forcing values, continuous sorted unique days, explicit start state and snow state, nonnegative irrigation, enough profile depth and every layer, no overlapping crops. Retain mass-balance checks. Upstream computes stress from opening storage before today's rain and suppresses all ET under snow (no sublimation); document these approximations. A closed budget verifies accounting, not predictive accuracy.
- Calendar rule: inclusive sow-through-harvest day count minus union of explicit inclusive dormancy windows must equal sum of active phase lengths. Define active index starting0; test every boundary, leap day, cross-year Southern/Northern seasons, and clipped/invalid windows. Do not invent a planting date from latitude alone.
- No LICENSE/COPYING/NOTICE file was found in this clone. User authorization to reuse teammate work does not supply an OSS license label. Preserve author, source repository/branch/SHA, original file checksums, adaptations and `rights unspecified` metadata; do not claim permissive licensing.

README v6's historical surface-moisture experiment reports raw ERA5 versus 2-day-lag SMAP-assisted correction on IFC farms2025 RMSE0.074→0.071 m3/m3, correlation0.60→0.67; no-L3 historical2018–20 RMSE0.085→0.086. Iowa regional phenology calibration1991–2010/test2011–25 gives maize flowering MAE1.8d and soybean3.9d. These are different tasks and populations. Its actual crop root-water event hindcast has only about24 cases/date and operational Brier skill -0.02/0.06/0.03 at June1/June15/July1, while actual-weather-oracle skill is higher. There is no validated absolute crop yield in these claims. Daily active soil sensors outperform the reconstruction model; retrospective ERA5 is not an operational nowcast. Preserve these distinctions in the imported model card.

PCSE-specific caveat matters for winter: default [Wofost72_WLP_CWB configuration](https://raw.githubusercontent.com/ajwdewit/pcse/master/pcse/conf/Wofost72_WLP_CWB.conf) selects `WaterbalanceFD`. The separate [WaterbalanceFDSnow](https://raw.githubusercontent.com/ajwdewit/pcse/master/pcse/soil/classic_waterbalance.py) explicitly documents that snow and soil are independent and rainfall still enters the soil as if no snow; it is not proof of coupled snow-water conservation. Its crop-finish root redistribution does preserve water across changing root depth. A separate snow module's presence in a repository is insufficient for claiming the chosen adapter includes it.

[Wheat parameter YAML](https://raw.githubusercontent.com/ajwdewit/WOFOST_crop_parameters/wofost72/wheat.yaml) explicitly declares Europe coverage/EUPL and winterwheat `IDSL=2` (temperature+daylength+vernalization), with vernalization parameters. [Phenology source](https://raw.githubusercontent.com/ajwdewit/pcse/master/pcse/crop/phenology.py) implements thermal response/vernalization and can force completion after a critical stage with warning. These need cultivar/local phenology observations. [Official7.2 crop list](https://raw.githubusercontent.com/ajwdewit/WOFOST_crop_parameters/wofost72/crops.yaml) contains wheat, maize, soybean, barley, sunflower, rapeseed, rice but no field pea. Files now live on version-specific branches; snapshot matching branch/checksum, never moving master/network retrieval at request time.

One defensible published process-model metric: the [2026 Nebraska APSIM-NG winter wheat study](https://www.frontiersin.org/journals/agronomy/articles/10.3389/fagro.2025.1740421/full) calibrated two cultivars with two growing seasons and four N rates, then validated29site-years across five Nebraska counties2017–22. Yield validation RRMSE was14% for LCS and19% for WB; calibrated phenology RMSE3–5days. It does not establish superiority on Field Shift, other crops, Ukraine, or global uncalibrated soils. No same-split eight-crop ranking among AquaCrop/WOFOST/DSSAT/APSIM was found in this audit; do not invent one from disparate papers.

## Learned yield and EO challengers: metrics with their actual target

1. **Mean/trend/Ridge/RF/GBDT.** CPU-feasible and essential baselines, requiring observed yield labels and information available at the decision date. CY-Bench's final2026 paper is explicitly an administrative maize/wheat dataset and illustrative evaluation, not a field-yield SOTA certificate. [March2025 v1.8 upstream result table](https://raw.githubusercontent.com/WUR-AI/AgML-CY-Bench/main/results_baselines/tables/tables_march2025_v1_8.md) reports median LOYO NRMSE: US maize mean20.16%, trend21.84%, RF residual22.07%, Ridge residual22.04%, RF24.60%, Ridge27.66%; China maize mean9.38%, RF residual7.74%. This establishes region dependence in that version only, not a current universal ranking or an ARDN expectation. [Final paper](https://essd.copernicus.org/articles/18/3997/2026/essd-18-3997-2026.html) covers38maize/29wheat countries, with Ukraine absent. Forecast lead time, dataset release, spatial aggregation and fold summary must match before comparison.

2. **Prithvi-EO2.0.** [Paper](https://arxiv.org/abs/2412.02732):4.2M global HLS time-series samples,30m,300M/600M variants; reported600M average improvement8% over Prithvi1 on GEO-Bench tasks. This is EO transfer performance, not yield RMSE. [Current model card](https://huggingface.co/ibm-nasa-geospatial/Prithvi-EO-2.0-600M) has Apache2 weights and also5M tiny-TL and100M-TL variants. With real pre-cutoff imagery, the tiny frozen encoder plus Ridge/GBDT is a plausible bounded CPU experiment; label-trained head, cloud masks, exact bands/scales and checkpoint checksum remain necessary. No foundation pretraining from scratch proposed.

3. **TerraMind1.0 base/large.** [Paper Table6](https://arxiv.org/html/2504.11171v3) frozen encoders with learned heads on nine PANGAEA datasets: mean mIoU58.35(base)/59.57(large) versus CROMA55.29 and task-trained U-Net57.58; PASTIS crop segmentation40.51/43.13, not yield. Pretraining base cost9216A100 GPU-hours (32GPUs12days), so unsuitable from scratch here. [Model card](https://huggingface.co/ibm-esa-geospatial/TerraMind-1.0-base) Apache2; Sentinel1/2, DEM and other modalities. Artificially generated modalities must remain labeled synthetic and cannot become ground-truth validation inputs.

4. **PhenoYieldNet (CVPR2026 paper), not universal production model.** [Paper](https://arxiv.org/html/2605.23478v1): CropNet11USstates, county yield, train2020/test2021; four crops. Table2 multicrop RMSE corn16.52bu/ac, soy5.91bu/ac, winterwheat8.32bu/ac, cotton54.88lb/ac; XGBoost respectively22.72/7.59/10.68/84.47. Uses SpectralGPT,200epoch adaptation+100epoch head training, A6000. Main comparison is not pre-sowing; separate progressive in-season experiment exists. Only three of our catalog crops overlap. The article license is not proof of code/checkpoint/data deployment rights. Do not compare its county RMSE directly with plot-level ARDN or infer unsupported crops from a crop embedding. Reproduce exact metric definitions and splits before calling it SOTA locally.

## Global registry and coverage policy

Recommended record key: model family/version + crop botanical identity/usage + cultivar/ecotype + region/agroecozone + production system + calendar version. Fields:

- Source publisher/DOI/URL, source revision/checksum, extraction page/table, unit, original range, chosen value, transformation, license/rights and attributable author.
- Geographic validity polygon or declared region, season/winter-spring identity, actual sow/harvest year and date, explicit dormancy windows, irrigation/paddy class, phenology method, required weather/soil/management, compatible model class and parameter schema.
- Separate status dimensions: reference-only, locally calibrated, independently validated, extrapolated/out-of-domain; parameter availability versus runnable versus scientifically validated. Never collapse them into `supported=true`.
- Evaluation target/unit/depth, split IDs and cutoff, sample/farm/year counts, baseline and model scores, uncertainty intervals, failure groups, holdout contamination status, model/data/parameter hashes. Surface m3/m3 and root-zone mm remain distinct.

[FAO crop calendar](https://cropcalendar.apps.fao.org/?language=en&pagename=%2Fwelcome.do) is an agroecozone reference. [MIRCA-OS v2 March2026](https://hydroshare.cuahsi.org/resource/e4582ca0042148338bb5e0148b749ed6/) provides23cropclasses, irrigated/rainfed,2000–2020 at5year intervals,5arcmin grids and CSVcalendars. Its calendars/monthly areas are historical regional priors; not exact current farm dates, with known few-pixel area inconsistencies. [GGCMI Phase3](https://zenodo.org/records/5062513) and [ISIMIP May2026 calendar update](https://www.isimip.org/gettingstarted/input-data-bias-adjustment/details/115/) offer crop-specific winter/spring and climate-adaptive scenarios. Do not silently map broad pulses to fieldpea or arbitrary date-of-month to observed sowing. [FAO AquaCrop input requirements](https://www.fao.org/aquacrop/overview/input-requirements/) likewise distinguish calibrated crop properties from cultivar/local adjustments.

Abstain when missing calendar, incompatible crop/system, unqualified cultivar, unsupported salinity/flooding/groundwater/N process, insufficient profile depth, missing required weather, non-cropland/ocean/ice land cover, inaccessible source/license or out-of-domain deployment. Geographic coordinates or latitude band alone cannot establish agricultural suitability. Allow a clearly labeled generic reference scenario only with explicit assumptions, never an invented calibrated fallback.

## Evidence needed before promotion

1. Numerical correctness: daily mass balance incl snow/irrigation/runoff/deep drainage, monotonic/finite/physical bounds, root-depth changes and fallow continuity, no hidden reset at crop switch; calendar/date/leap/hemisphere invariants.
2. Actual paired prediction evidence: training-only preprocessing/calibration, held-out years and held-out sites/countries, nested hyperparameter tuning, declared issue-time features. Existing opened holdouts become diagnostic, not fresh independent proof.
3. Score by target: surface moisture MAE/RMSE/bias m3/m3 at sensor depth; root reserve mm at matched profile; phenology MAE days; absolute yield MAE/RMSE t/ha plus NRMSE with denominator stated; event Brier/CRPS/reliability; intervals empirical coverage and width. Correlation cannot substitute for unbiased error.
4. Paired confidence intervals clustered by independent farm/year, group worst-case checks (crop/region/drought/irrigation/calendar), missing-data and out-of-domain rates, and runtime/RSS measurements. Keep strong climatology/mean/trend/persistence baselines and fail promotion if gains are statistically or operationally unconvincing.
5. Decision selection: apply economic ranking only to comparable target estimates with explicit user price/cost/yield assumptions. If the model yields water stress only, abstain from modeled profit/yield claims. Evaluate selected-plan regret/risk under held-out scenarios separately from process RMSE.

Remaining limitations: no universal engine ranking; no new GPU or paid calls; no new accuracy test run by this researcher; no proof of global locally calibrated eight-crop yield coverage; exact archived dataset and upstream version bytes must be frozen by implementation. The phased path above increases honest process coverage and reproducibility while making those gaps visible.
