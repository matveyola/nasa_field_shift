# CPU benchmark interpreter protocols

The CPU benchmark is a deterministic synthetic contract check, not an empirical
crop-accuracy result. It records interpreter, engine, input and evaluation
identities alongside numerical outputs. `field_shift_models.cli.stable_report`
excludes only runtime resource measurements (CPU time, elapsed time and peak RSS);
interpreter metadata remains part of its strict equality check.

| Report | Actual interpreter | Use |
| --- | --- | --- |
| `packages/field-shift-models/reports/cpu-v6.json` | CPython 3.12.16 | Preserved historical execution after explicit land-evidence qualification |
| `packages/field-shift-models/reports/cpu-v7.json` | CPython 3.12.13 | Planning CI protocol available through pinned uv 0.11.0 |

CPU-v7 is the unmodified output of an actual locked execution on published
`36ea6b4ce732d6ecb12737021bfaa42dffdd1870`, using a fresh environment and uv-managed
CPython 3.12.13. No source, dependency lock, parameter or model calculation changed.
The report SHA256 is
`78f7413365f0221a6fcb7f90eef86499395d5b76ed98fecb1a3eb31ccf556d87`.
CPU-v6 remains byte-identical, SHA256
`9f158233d6958872b83d6d9ab2436c0e2a477b59c6c5fd7a605d6a674899dacb`.

The actual comparison found exactly one differing stable field: `python`, from
`3.12.16` to `3.12.13`. All engine manifests, input/evaluation hashes, applicability,
seasonal outputs and numerical results agree exactly. The raw reports differ at
37 paths: that interpreter field and 36 existing resource measurements across
four crop/weather cases and three engines. These results justify a new explicitly
versioned execution protocol; they do not justify ignoring interpreter identity,
changing tolerances or relabeling a report generated by another interpreter.

The planning job pins both setup-uv's `python-version` and the model environment's
`uv sync --python` to `3.12.13`, then checks CPU-v7. A cross-file test reads the
actual workflow command and selected report to require matching patch versions.
The regression comparing v6/v7 retains strict comparison of every other stable
field and the immutable v6 checksum. `stable_report` and CLI checks are unchanged.

To reproduce the CI protocol from the repository root with uv 0.11.0:

```sh
uv sync --project packages/field-shift-models --locked --python 3.12.13
packages/field-shift-models/.venv/bin/python -m field_shift_models.cli benchmark \
  --check packages/field-shift-models/reports/cpu-v7.json
```

Use separately owned environments for other interpreter protocols. Under
3.12.13, CPU-v6 must fail; under 3.12.16, CPU-v6 passes and CPU-v7 must fail. An
interpreter-only mismatch is still a real protocol mismatch. Future interpreter
updates require actual execution, exact comparison, a new retained report when
needed, and independent review before changing the CI target. No report establishes
observed yield accuracy or promotes a scientific model.
