# Field Shift · API сівозмін і сценаріїв водного балансу

Цей пакет можна запустити як окремий сервіс сівозмін і підключити до застосунку через HTTP. Почніть із [плану інтеграції](#інтеграція-в-застосунок) і [короткої перевірки](#перевірка-каталогу-і-sutherland-5050).

## Як підтягнути гілку

Виконайте з кореня клона `matveyola/nasa_field_shift`.

```bash
git fetch origin
git switch research/rotation-handoff
git merge --ff-only origin/research/rotation-handoff
cd research/rotation-handoff
```

Якщо працюєте з ZIP, відкрийте папку, де лежить `app.py`. Для локальної перевірки використовуйте Python 3.12. Перше встановлення залежностей потребує інтернету. Каталог і тестові приклади запускаються без бази даних, Redis і ключів погодних сервісів. Розрахунок прогнозу на довільну дату або координати може завантажувати дані зовні.

## Інтеграція в застосунок

1. **Підключіть сервіс через бекенд.** Використовуйте налаштовану адресу сервісу сівозмін і схему [`openapi.json`](openapi.json). У ній адреса `127.0.0.1:8081` призначена для локального запуску. На сервері задайте адресу, доступну бекенду або асистенту. Для полів ферми збережіть перевірку доступу в основному бекенді. Для інтеграції з UI орієнтуйтеся на [наявний API-клієнт сівозмін](../../apps/web/src/api/rotationPlanning.ts). Результати сервісу використовуйте для попереднього перегляду, а збереження й підтвердження планів виконуйте через `/api/rotations/planning/*`.
2. **Заповніть вибір поля й культури.** З `GET /api/rotations/forecast/catalog` беріть `fields[].id` і `crops[].id`, які в запитах передаються як `field_id` і `crop_id`. Запит `GET /api/rotations/cultivar-references?crop_id=soybeans&region_code=US-IA` повертає сорти сої для Айови. Покажіть `name`, `kind`, `trial_location`, `trial_years` і `source_url`. Дані випробувань показуються довідково. Для розрахунку окремих гібридів кліматичний маршрут використовує `hybrid.stage_lengths` із джерелом, якщо передано підтверджену тривалість усіх чотирьох фаз. [Контракт каталогу й гібридів](CLIMATE_API.md#метрики-кожного-кандидата)
3. **Виберіть маршрут за режимом.**

   | Режим | Що викликати |
   | --- | --- |
   | Порівняння 2–3 планів на майбутні дати сівби | `POST /api/rotations/forecast`. Передайте поле та дати, покажіть джерела актуальної й архівної погоди з `weather_segments`. [Запити та поля відповіді](HYBRID_FORECAST.md) |
   | Поетапний вибір культур для 2040–2049 | `POST /api/rotations/climate/step`. Покажіть `top_candidates`. Для наступного кроку передайте попередній `choice` з датою сівби в `selected`. Для порівняння завершених планів викликайте `POST /api/rotations/climate/compare`. Ці маршрути використовують код Руслана. [Готові JSON-запити](CLIMATE_API.md) |
   | Демонстрація Sutherland 2027, 50% історія і 50% NASA | Для картки демо використовуйте [збережений JSON](examples/sutherland-2026-28/result-nasa-2027.json) із позначкою «офлайн-сценарій для Sutherland». Порядок культур є в `ranking_by_water_shortfall.ensemble`, числа — у `candidates`. Приклад відтворюється локальним скриптом. Для розрахунку 50/50 за запитом потрібен окремий HTTP-маршрут. |

4. **Додайте джерела до картки й відповіді асистента.** Показуйте сценарій, дати й одиниці. Дефіцит у відсотках — це частка незадоволеної потреби культури у воді. Для `null` показуйте «немає оцінки». Агенту передайте схему, [опис роботи з API](RAG_HANDOFF.md) і [правила відображення та переходу між сезонами](UI_AND_ASSISTANT.md). [Наявний адаптер Marsden](../../services/agent/agent_service/integrations/marsden.py) вже прокладає шлях до `assessment`. Для каталогу, `forecast` і кліматичних маршрутів додайте потрібні виклики в адаптері.

## macOS або Linux

```bash
python3 -m venv .venv
.venv/bin/python -m pip install -r requirements.txt
.venv/bin/python -m uvicorn app:app --host 127.0.0.1 --port 8081
```

## Windows PowerShell

```powershell
py -3 -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
.\.venv\Scripts\python.exe -m uvicorn app:app --host 127.0.0.1 --port 8081
```

Залиш термінал із сервером відкритим. У браузері відкрий [Swagger](http://127.0.0.1:8081/docs), розгорни `POST /api/rotations/assessment`, натисни **Try it out**, встав вміст `examples/request.json` і натисни **Execute**. У відповіді має бути код `200` і три сценарії по два плани. У кожному сценарії видно обраний рік і два роки, на погоді яких розраховані плани. [Каталог можна відкрити напряму](http://127.0.0.1:8081/api/rotations/assessment/catalog)

Якщо порт `8081` зайнятий, заміни його в команді запуску й у посиланні, наприклад на `8082`. Для зупинки сервера натисни **Ctrl+C**.

## Перевірка каталогу і Sutherland 50/50

- Відкрийте [каталог гібридів і сортів](http://127.0.0.1:8081/api/rotations/cultivar-references). Очікується **20 записів**. За [фільтром сої для Айови](http://127.0.0.1:8081/api/rotations/cultivar-references?crop_id=soybeans&region_code=US-IA) має бути **5 записів із Sutherland**.
- У другому терміналі відкрийте `research/rotation-handoff` і запустіть офлайн-приклад. У `--ruslan-dir` підставте шлях до папки `research/fieldshift_tasks`, де лежить `fstasks/balance.py`. Орієнтир версії — коміт `468a03d`. [Гілка Руслана](https://github.com/matveyola/nasa_preparation/tree/research/fieldshift-tasks-1-4)

```bash
.venv/bin/python replay_sutherland_2026_28.py --ruslan-dir "/шлях/до/nasa_preparation/research/fieldshift_tasks" --nasa-2027 --output sutherland-check.json
```

На Windows використайте `./.venv/Scripts/python.exe` замість `.venv/bin/python` і свій шлях до коду Руслана. У `sutherland-check.json` обидві ваги в `ensemble` мають бути `0.5`. Очікуваний порядок у терміналі — `wheat_spring, maize_grain, sunflower, soybeans`.

## Перевірка з другого термінала

У цій самій папці виконай одну команду для своєї системи. Перевірка працює і без завантаження Swagger.

```bash
.venv/bin/python check.py
```

```powershell
.\.venv\Scripts\python.exe check.py
```

Перевірка має завершитися повідомленням `OK`. Для іншого порту додай `--base-url http://127.0.0.1:8082`.

## Перевірка результату між роками

Після встановлення залежностей запусти команду зі своєї системи. Для цієї перевірки сервер можна залишити вимкненим.

```bash
.venv/bin/python check_year_behavior.py
```

```powershell
.\.venv\Scripts\python.exe check_year_behavior.py
```

За однакових добових опадів, температури й випаровування в тій самій послідовності від сівби, а також однакового ґрунту й стартової вологості, та сама культура дає однаковий розрахований дефіцит у різних календарних роках. За інших умов дефіцит може змінитися. Коефіцієнти потреби у воді задані окремо для кожної культури й фіксовані в межах версії API. Ця перевірка підтверджує повторюваність розрахунку. Для оцінки польової похибки потрібні вимірювання на ділянці.

## Вибір ділянки

Підстав у `field_id` ідентифікатор із каталогу. У пакеті доступні `marsden_demo` (Marsden Farm), `sutherland_nw` (Northwest ISU-RDF, Sutherland) і `crawfordsville_se` (Southeast ISU-RDF, Crawfordsville). Для кожної ділянки роки підбираються за її погодою за 2017–2026 роки. Оцінки показують, як плани працювали б за історичних умов, і діапазон результатів у цій вибірці.

У двох планах кукурудза й соняшник міняються роками. Обидва плани отримують той самий ряд погоди для кожного року. Початковий стан ґрунту в обох планах визначає архівна вологість кожного сезону.

## Додавання ділянок

Для прогнозного маршруту можна відразу передати координати нового поля. Для координат із покриттям SoilGrids сервіс завантажить ґрунтовий профіль і підбере національні довідники за країною. [Запит для іншої країни](HYBRID_FORECAST.md#довідкові-дані-для-інших-країн)

Щоб зберегти власну ділянку в локальному каталозі історичних оцінок, використовуй імпорт.

Створи `fields-to-add.json` із масивом ділянок. Для кожної вкажи `id`, `name`, `latitude`, `longitude`, `soil_source_url` і `soil_layers`. Кожен шар має поля `top_m`, `bottom_m`, `field_capacity`, `wilting_point`. Глибини в метрах, польова вологоємність і точка в'янення у м³/м³. Додатково можна вказати `location_source_url`. Використовуй профіль саме для цієї ділянки, який покриває глибину кореневої зони до 1 м.

Для пробного запуску передай `examples/fields-to-add.json` замість власного файлу. У ньому вже є координати й профіль ґрунту для четвертої ділянки, біля Nashua. Імпорт за замовчуванням бере десять останніх повних сезонів травень–вересень і один попередній сезон для дворічного розрахунку. [Готовий приклад для Nashua](examples/fields-to-add.json)

```bash
.venv/bin/python import_fields.py fields-to-add.json
```

```powershell
.\.venv\Scripts\python.exe import_fields.py fields-to-add.json
```

Під час імпорту потрібен інтернет для завантаження історичних даних за координатами. Після імпорту перезапусти API, перевір новий `field_id` у каталозі й використовуй його в запиті. Подальші розрахунки читають збережені дані локально.
