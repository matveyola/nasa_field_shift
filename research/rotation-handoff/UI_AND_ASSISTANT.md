# Вибір дати сівби в інтерфейсі й асистенті

Дайте фермеру два входи — **«Коли краще сіяти?»** та **«Я вже знаю дату»**. В обох випадках фермер підтверджує дату, і сервер розраховує культури саме для неї. Вікно сівби є підказкою з агрономічного джерела. Рейтинг культур і водні показники надходять із розрахункового API.

## Перший посів

1. Запитайте поле з каталогу або координати, дату сівби, один пріоритет і за потреби доступну техніку. Якщо фермер уже назвав поле й дату, переходьте до розрахунку без повторного запитання. Якщо дату ще не вибрано, покажіть вікна для культур, щодо яких є регіональні дані. Якщо відома тільки культура, уточніть місце. Для вікна покажіть джерело, географію й умови початку сівби.
2. Підпишіть **«Довідкове вікно»**, якщо це календар з регіональних дослідів. Для Sutherland приклад для кукурудзи — **15 квітня–9 травня**. Ближче до сівби перевіряйте температуру ґрунту на глибині посіву, короткий прогноз, ризик похолодання й стан поля. Для кукурудзи Iowa State наводить близько **10 °C** у ґрунті з очікуваним потеплінням. Регіональне вікно саме по собі не підтверджує готовність поля в конкретний день. [Дослід Iowa State зі строками сівби](https://acsess.onlinelibrary.wiley.com/doi/10.2134/cftm2017.02.0015) · [Умови для початку сівби](https://crops.extension.iastate.edu/post/soil-temperature-and-planting-conditions-what-watch-spring)
3. Після підтвердження дати викличте `POST /api/rotations/climate/step`, якщо запит належить до підтримуваного кліматичного режиму. Передайте дату як `planting_date` у форматі `YYYY-MM-DD`. Для першого посіву `selected` порожній. Якщо користувач хоче порівняти дві дати, виконайте два запити з тим самим полем, набором культур, попередниками, пріоритетом і сценаріями. Називайте результат порівнянням за вибраною метрикою. Водний дефіцит сам по собі не дає максимуму врожайності.

Приклад нейтральної підказки асистента — «Для кукурудзи біля Sutherland довідкове вікно — 15 квітня–9 травня. Ближче до сівби перевірте, чи ґрунт на глибині посіву прогрівся приблизно до 10 °C і чи поле придатне до робіт. Якщо хочете сіяти 1 травня, порівняю варіанти для цієї дати». Для інших регіонів використовуйте їхні джерела. Якщо довідкових даних бракує, покажіть «регіональне вікно невідоме» й залиште ручний вибір дати.

## Картка для вибору культури

| Що показати | Що читати з відповіді `climate/step` |
| --- | --- |
| Перші три доступні варіанти | `top_candidates`. Порядок за одним пріоритетом доступний за `ranking.status = ranked`. За `priority_unavailable` показуйте варіанти без місць і повідомляйте, якої метрики бракує. |
| Повний список, у тому числі виключені варіанти | `candidates`, `status`, `reason`, `warnings`, `feasibility`, `blockers`, `equipment_to_confirm`. `below_regional_crop_return_interval` означає, що культуру виключено з топу за регіональним довідником. `needs_confirmation` означає, що доступ до обладнання ще треба уточнити. |
| Вода | `water.water_deficit_pct`, `water.water_deficit_mm`, `water.drought_stress_days`. У `scenarios` є окремі цифри по кожній кліматичній траєкторії. Медіана днів може бути дробовою. |
| Економіка | Покажіть **«Виручка від продажу врожаю»** з `economics.gross_revenue_per_ha` і **«Виручка після вартості насіння»** з `economics.revenue_after_seed_per_ha`. Поруч покажіть `seed_cost.cost_per_ha`, `seed_cost.source`, `price_reference_years` і валюту. Якщо друге число порожнє, поясніть, що бракує вартості насіння в сумісній валюті або виручки. |
| Інші показники | `water.living_cover_days`, `agronomy.candidate.harvested_nutrients`, `national_nutrient_reference`, `erosion`. Усі доступні показники показуйте і при фінансовому пріоритеті. |
| Джерела й пропуски | `weather_source_url`, `weather_cases`, `thermal_reference`, `field.soil_source`, джерела для конкретної метрики. `null` відображайте як «оцінки немає». `0` використовуйте для розрахованого нуля. |

Для вибраної культури збережіть `choice` та її підтверджену дату як `planting_date`. На другому кроці передайте один запис у `selected`, на третьому — два у хронологічному порядку. Користувач може змінити попередній вибір. У такому разі перераховуйте всі наступні кроки з оновленим `selected`. Якщо він змінив регіон або поле, починайте окремий план, бо джерела й ґрунт змінюються.

## Що пояснити після вибору культури

Покажіть окремо чотири речі. За різних дат у погодних сценаріях покажіть діапазон або окремі сценарії.

1. **Коли може звільнитися поле.** `scenarios[case].end_date` та `end_reason` показують розрахункову стиглість чи завершення через мороз. Для наступної сівби враховуйте реальну або заплановану дату збирання. Вона може бути пізнішою за дату стиглості.
2. **Скільки води лишається й коли вона поповнюється.** `profile_closing_mm` — запас наприкінці змодельованого сезону. `post_crop_recharge` дає перший день до кінця року з не менш ніж 80% місткості профілю. На наступному кроці `recharged_to_80pct_after_previous_end_on` охоплює проміжок до нової сівби. Поріг 80% прийнято для порівняння. Підписуйте «поповнення води». За відсутності дати покажіть, до якого дня її шукали.
3. **Яка пауза до запропонованої сівби.** `fallow_days_before_planting` рахує повні дні між змодельованим кінцем попереднього росту й новою датою. Це довжина заданого проміжку. Наступна культура може вимагати дочекатися іншого вікна, поки ґрунт прогріється, підсохне або завершиться збирання. Наприклад, після кукурудзи Sutherland у демо вода досягла порога за 8 днів, а до сівби наступної весни було 232 повні дні.
4. **Коли повертають ту саму культуру.** Якщо є правило, покажіть `disease_guidance`, `disease_interval_status` та `same_crop_return_reference_year`. Це інтервал між посівами конкретної культури для керування ризиком хвороб. У проміжні сезони поле може бути під іншими культурами. [Приклад настанови щодо соняшнику](https://www.extension.iastate.edu/alternativeag/files/documents/sunflower_crop_guide.pdf)

У майбутньому наступну дату слід добирати від звільнення поля з урахуванням вікна наступної культури, запасу води, техніки й достатнього часу до заморозку або кінця сезону. У теплому регіоні можливий другий посів у тому самому календарному році. Для такої рекомендації модель має перевірити, чи посіви не перекриваються і чи друга культура встигає пройти фази в кожному сценарії. Фіксованої вимоги залишати поле без культури 200 днів немає.

## Що доступно в цій версії

| Можливість | Статус |
| --- | --- |
| Розрахувати топ на дату, обрану фермером, і передати вибір у наступні два кроки | Є в `climate/step` для 2040–2049, сівби з березня по липень і одного посіву на рік. |
| Запропонувати регіональне вікно сівби в асистенті | Є сценарій діалогу та джерело для прикладу Sutherland. Загального API календарів і автоматичної перевірки готовності ґрунту немає. |
| Вважати поле звільненим у конкретний день | API повертає модельний кінець росту. `min_next_planting_date` у кліматичному режимі відображає межу підтримуваних дат з 1 березня наступного року. Підтвердження збирання потрібне окремо. |
| Показати Sutherland 2026–2028 з перенесенням балансу Руслана | Є відтворюваний офлайн-приклад у пакеті. Публічного маршруту для цього прогону немає. |
| Перерахувати сценарій Sutherland 2027 з вагами 50/50 | `POST /api/rotations/scenarios/sutherland-2027` без тіла. Покажіть `ranking_by_water_shortfall.ensemble` та `candidates` з позначкою сценарію. Дані й дата сівби фіксовані. [Як запустити](README.md#перевірка-каталогу-і-sutherland-5050) |
| Запустити короткий прогноз для введеної майбутньої дати | Є `POST /api/rotations/forecast`. Усередині сезону він продовжує баланс із прогнозної погоди на історичні аналоги. Кожен наступний сезон цього маршруту має свою стартову вологість. |
| Три товарні посіви за два календарні роки з перенесенням води між ними | Залишається реалізувати у поетапному API, з перевіркою фактичного завершення, перекриття, посівних вікон і сезонних обмежень. |
